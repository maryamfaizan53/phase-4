# Phase IV: Kubernetes Deployment Constitution

## 1. Purpose

This constitution governs **Phase IV** of the Todo Chatbot project.

The objective of Phase IV is to deploy the existing Phase III Todo Chatbot (frontend + backend) on a local Kubernetes cluster using Minikube, with AI-assisted DevOps tooling.

**This phase focuses exclusively on infrastructure automation and deployment. No new application features are to be added.**

---

## 2. Project Scope

### In Scope
- Containerization of existing frontend and backend applications
- Use of Docker Desktop and Docker AI Agent (Gordon)
- Local Kubernetes deployment using Minikube
- Helm Charts for Kubernetes packaging
- AI-assisted Kubernetes operations using kubectl-ai and Kagent
- Agentic Dev Stack workflow: Spec → Plan → Tasks → Implement

### Out of Scope
- Adding new UI features
- Modifying business logic
- Changing database schemas
- Manual infrastructure scripting
- Manual YAML or Dockerfile authoring (unless generated by AI)

---

## 3. Core Principles

### I. Spec-Driven Development
**Mandatory Flow:** Specification → Plan → Tasks → Implementation

All work must originate from an approved specification. No ad-hoc or manual changes are allowed.

- **Documentation First**: All infrastructure changes must be specified before implementation
- **Traceability**: Every deployment artifact must be traceable to a spec document
- **PHR Requirement**: Prompt History Records created for every significant interaction
- **No Assumptions**: Never invent infrastructure patterns or configurations without specification

**Rationale**: Infrastructure-as-code requires the same rigor as application code. Unspecified changes lead to configuration drift and deployment failures.

### II. Agentic Execution
**Agent-Driven Workflow:** All work must be executed by explicitly defined agents operating only within their allowed scope.

- **Single-Agent Tasks**: Each task is assigned to exactly one agent
- **Scope Boundaries**: Agents MUST NOT operate outside their defined file paths and tools
- **No Manual Overrides**: Human must not manually execute tasks assigned to agents
- **Orchestrator Control**: Claude Code acts as orchestrator, enforcing agent assignments

**Rationale**: Multi-agent systems require strict role separation to prevent conflicts and ensure accountability. Each agent has specialized skills for its domain.

### III. AI-First DevOps
**Tooling Priority:** Prefer AI-assisted tools over manual CLI commands. Docker AI (Gordon), kubectl-ai, and Kagent must be used where applicable.

- **Gordon for Docker**: Use Docker AI agent for Dockerfile generation and image optimization
- **kubectl-ai for K8s**: Use AI-powered kubectl for deployments and scaling
- **Kagent for AIOps**: Use AI agent for cluster diagnostics and optimization
- **Fallback Rule**: If AI tool unavailable, Claude Code may generate equivalent CLI commands

**Rationale**: AI-assisted DevOps tools reduce human error, provide best-practice recommendations, and accelerate infrastructure tasks.

### IV. Single-Task Execution
**Sequential Processing:** Only one task may be executed at a time. The system must stop after each task for review.

- **No Parallel Tasks**: Tasks execute sequentially in dependency order
- **Checkpoint After Each**: Orchestrator pauses after each task completion
- **User Review**: Human reviews output before proceeding to next task
- **No Batch Execution**: Multiple tasks cannot be bundled into single execution

**Rationale**: Infrastructure changes are high-risk. Pausing after each task allows validation and rollback before compounding errors.

## 6. Execution Rules

### Workflow
All implementation must follow:
**Spec → Plan → Tasks → Implement**

### Task Execution
- Tasks MUST be executed sequentially
- After each task:
  - Output must be explained
  - Execution must pause for user review
- No task may exceed its assigned agent's scope

### Error Handling
- If a task fails, execution halts immediately
- Orchestrator reports failure reason and suggests remediation
- User decides whether to retry, skip, or abort

### Rollback Policy
- Each task should be reversible
- Orchestrator maintains rollback instructions for destructive operations
- User can request rollback to previous stable state

## 7. Success Criteria

Phase IV is considered complete when:
- ✅ Frontend and backend are containerized
- ✅ Images run successfully on Minikube
- ✅ Helm charts deploy the application
- ✅ kubectl-ai is used for deployment or scaling
- ✅ Kagent is used for cluster analysis
- ✅ The system runs locally without errors

### Acceptance Testing
- Application accessible via Minikube IP
- Frontend can communicate with backend
- Database persistence verified across pod restarts
- Scaling operations successful (replicas 1→3→1)
